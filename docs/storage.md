# 多存储配置

系统管理 → 存储管理支持多个本地目录和 S3 兼容配置。可新增、编辑、读写删除测试、设置默认、停用与删除配置。首次启动自动登记稳定 ID `local`，既有图片不改变链接或存储标识。

上传可传 `storage_id`，留空采用当前默认配置。图片一旦入库即绑定配置，切换默认值不会迁移旧文件。停用只禁止新上传，旧图读取、删除和失败重试仍正常执行。默认配置不能停用；默认配置和初始 `local` 配置不能删除。有任何图片记录（包括待删除）引用时，禁止删除配置或改变类型、目录、Endpoint、Region、Bucket、前缀、寻址方式。需要搬迁时另建配置并单独安排迁移。

## 本地

目录位于运行 Go 服务的服务器，不是浏览器所在电脑。相对路径保存时转换为绝对路径。容器只允许写入已挂载且当前 UID 有权限的目录；默认 `/data/uploads`。不要把目录放进前端静态资源目录。

## S3

填写名称、Region、Bucket、Access Key、Secret Key；Endpoint 留空使用 AWS S3，也可填写不带路径的 HTTP(S) 服务地址。自建服务通常使用 Path Style；具体以供应商要求为准。对象前缀可选，例如 `qpix`。不会自动创建 Bucket。生产服务使用 HTTPS。

配置使用 AWS SDK for Go v2，通过 SigV4 认证，执行 PutObject、GetObject、DeleteObject。访问凭据需要对应 Bucket / 前缀的对象读、写、删除权限，不需要 ListBucket。连接测试会写入 `.qpix-probe/<随机 ID>.txt`，读取校验后删除；失败会再尝试清理。探测结果只说明本次操作成功，不保证所有兼容服务的全部特性。

Bucket 保持私有。公开地址始终通过 QPix `/i/` 网关流式读取，才能应用 IP、Referer 和删除规则。不要向前端返回永久对象地址或绕过网关的公开 Bucket 地址。

## 凭据与主密钥

S3 凭据使用 AES-256-GCM 加密后写入数据库，并绑定存储配置 ID。接口只返回 `has_credentials`，不返回明文或密文；编辑时两项均留空保留原凭据，轮换时两项一起填写。

`QPIX_MASTER_KEY_FILE` 指定独立密钥文件（默认 `data/master.key`），首次启动创建，同时保护 S3 凭据与分享令牌。密钥文件必须与数据库一同备份并限制访问权限；Windows 需用目录 ACL 限制服务账号之外的访问。数据库中已有加密凭据或分享时，缺失、损坏或错误密钥会导致启动失败，不会自动重置密钥。数据库与密钥同时泄露时，加密不能继续保护凭据和分享令牌。

备份所有本地目录或 S3 对象，而不只是默认存储。配置中保存的位置恢复后必须存在且权限正确。当前仅支持单 Go 应用实例；存储配置缓存及上传/配置变更互斥都在该实例中维护。
