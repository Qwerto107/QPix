# 账号、相册权限、配额与分享

## 账号与相册

注册关闭。初始化账号为管理员；在“系统管理 → 用户管理”创建普通用户，可设置容量、单张大小、启用状态及密码。重置普通用户密码或停用账号时，撤销对应登录会话与上传 Token。管理员不能通过该入口被停用或重置密码，修改本人密码使用账号设置。

密码不强制最短长度或复杂度。账号密码必须非空、最多 72 字节，两次输入一致；编辑账号时两项均留空保留原值。72 字节来自 bcrypt 的技术上限，多字节字符按 UTF-8 字节数计算。分享密码留空表示无需密码。

相册由管理员创建、重命名和删除，默认私有。在相册卡片点击“权限”：

- 允许访客通过图片链接访问：未登录访客收到图片链接后可查看对应图片，上传仍需授权。
- 授权用户：被选中的账号可浏览、上传、重命名/移动/删除本人上传的图片。
- 管理员始终可以管理所有账号的图片。

未分类图片仅上传者和管理员可见。移动图片不改变上传者，目标相册须有上传权限。取消授权后，用户不能继续查看或操作该相册内的图片；管理员可将图片移回上传者的未分类空间。删除相册保留图片并返回各上传者的私有未分类空间，原相册访问权限停止生效。

不提供访客预览、公开相册目录或图片发现入口。用户上传后复制图片链接给访客；访客只访问收到的图片，或通过有效分享链接查看指定图片/相册。私有相册与未分类图片的裸链接不会绕过权限。普通用户登录后可查看授权相册，在图库选择“仅看我上传的图片”。普通用户不返回存储目录、Endpoint、凭据等管理配置。

列表、搜索、分页总数、相册计数、原图与缩略图都检查权限。无权访问私有图片时返回 404。图片响应使用 `private, no-store`，权限检查早于 ETag/304；S3 保持私有并通过 Go 读取。

## 配额

用户管理中的容量使用 GiB，单张使用 MiB，API 字段均为整数**字节**。

管理员通过“偏好设置 → 上传限制”控制服务器单张上限（1–100 MiB）。保存后新上传立即采用此值，数据库配置优先于启动默认值，重启后保留。新建用户默认填 0 跟随服务器；已有账号的独立限制保留，有效值取账号与服务器中的较小值。调低服务器上限不改写账号配置或删除图片；编辑原配置高于服务器的账号时，界面会填入当前有效值并提示保存后的行为。

- `quota_bytes = 0`：不限累计容量。
- `max_file_bytes = 0`：单张跟随服务器限制；设置值不能高于服务器当前上限。
- 单张限制检查上传原文件，不能通过选择压缩绕过。
- 容量按主文件保存大小累计，包含等待删除的记录，不包括缩略图、数据库或文件系统开销。
- 上传前按原文件大小预占，剩余容量必须能容纳原文件；压缩后按实际保存大小结算。失败时释放预占，完成物理删除后释放占用。
- 降低配额不会自动删除图片。用量超出配额时停止新上传，仍可删除。

容量预占、最终图片入库和预占释放在数据库事务中处理，并由单实例锁协调并发。启动时清除异常退出遗留的预占记录。当前仍仅支持一个 Go 服务实例，不能将该流程直接用于多实例部署。

## 分享

管理员可从“分享管理”、相册卡片或图片详情创建分享，目标为单张图片或整个相册。普通用户和访客不能创建分享。

- 密码可选，设置时最多 72 字节，不强制最短长度或复杂度；只保存 bcrypt 哈希，不回显。
- 到期时间可选，留空长期有效；界面使用当前设备本地时间，后端统一存储 UTC。
- 分享链接是独立的只读授权，允许查看私有相册中的指定内容。将相册改为私有不会撤销已有分享；需要在分享管理主动撤销。
- 相册分享实时包含该相册当前图片，新加入图片也会被分享；移出相册后原分享文件地址失效。单图分享持续指向该图片，移动不改变分享目标。
- 密码解锁状态通过 HttpOnly Cookie 保存，最长 24 小时且不超过分享到期时间。
- 撤销、到期、目标图片删除或目标相册删除后，分享页面、原图与缩略图均不可访问，已解锁 Cookie 也不能绕过。
- 分享页面 `/s/<token>` 内部使用 `/si/<token>/<file>` 读取图片，不返回私有 `/i/` 地址作为分享资源。

令牌使用高熵随机值，查找保存 SHA-256 哈希；为支持管理员再次复制链接，令牌同时使用独立主密钥加密保存。主密钥现在同时保护 S3 凭据和分享令牌，须随数据库备份。无密码链接持有者具有访问权限，转发链接意味着转发该权限。

复制受密码保护的图片地址不能代替分享页面：访问者需先在同站点分享页解锁。普通私有图片链接依赖登录会话，不用于无需登录的跨站嵌入。

## 上传 Token

上传 Token 可选择常用期限、自定义到期日期时间或永久，所有期限均可撤销。永久 Token 以空到期字段保存，同样检查账号启用状态、相册权限、上传限制及配额；停用、改密或主动撤销后失效。

## 网络规则与部署

所有账号统一使用 `/auth/*` 认证接口，登录页只输入用户名和密码。后端从数据库识别角色，账号密码验证成功后应用对应网络规则，规则通过才创建会话。管理员登录与操作使用 `admin` 规则，普通用户登录与操作使用 `images` 规则，上传使用独立 `upload` 规则。会话恢复、退出与改密也按当前角色检查；统一入口不会绕过管理员网络限制。分享及 `/i/`、`/si/` 均使用 `images` 规则。

IP / Referer、账号状态、相册权限和图片归属条件同时生效。应急开关 `QPIX_DISABLE_ACCESS_RULES` 仅跳过 IP / Referer，不跳过身份与资源权限。

Nginx 和 Vite 除原有 `/api/`、`/i/`，还需把 `/si/` 代理给 Go；仓库已包含配置。`/s/*` 作为分享 SPA 路径由前端处理。访问分享的域名需要同源代理这些路径；单独的图片域名仍可只代理 `/i/`。

共享缓存不能缓存 `/i/`、`/si/` 或接口。开启权限前已缓存的旧副本须由部署方清理；已下载或已显示的图片不能撤回。开发环境不要求保持旧测试数据及旧链接兼容。
