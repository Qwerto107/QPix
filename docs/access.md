# 访问控制

三组规则独立，默认全部关闭：

管理页面以列表展示三个范围的启用状态与规则数量，点击对应行“编辑规则”打开表单；取消编辑不改动已保存配置。

| 范围 | 覆盖请求 |
| --- | --- |
| admin | 管理员登录和系统管理接口；管理员通过登录会话操作图库/相册/Token 时同样校验，个人 Token 仅上传时校验 upload 规则，不限制前端 HTML/JS/CSS |
| upload | `POST /api/v1/images`，仅 IP 规则，Cookie 会话与个人 Token 均适用 |
| images | 仅 `/i/` 原图与缩略图直链；不含分享和普通用户操作 |

登录页统一输入用户名和密码，后端识别账号的实际角色，验证密码后仅对管理员应用 admin 网络规则，再创建会话。`/auth/me`、退出、改密同样按当前账号角色检查；管理规则不会误挡普通账号，统一登录也不会绕过管理员限制。

IP 白名单支持 IPv4、IPv6 和 CIDR，每组最多 200 项。Referer 使用域名或 IP，不含协议、端口、路径；`*.example.com` 允许各级子域名，但不包含 `example.com`。`badexample.com` 不会匹配。空 Referer 需单独允许，字符串 `null`、无效 URL 不算空。IP 和 Referer 同时启用时必须同时满足。限制不会代替登录、Token、Origin 和 CSRF 检查。

Referer 可以被客户端伪造或因浏览器策略缺失，用于防盗链而非身份验证。管理端保存规则前会检查当前请求仍能通过，避免立即锁住自己；之后网络/IP 变化仍可能失去访问。外链启用 Referer 限制时，若希望管理端预览正常，需要允许管理域名；图片域名跨源且前端 Referrer-Policy 为 same-origin 时也可能需要允许空 Referer。

## 相册 Referer 覆盖

在相册“访问设置”选择继承全局、自定义域名白名单或不限制 Referer。仅覆盖图片网关的 Referer 检查，全局 IP 限制仍有效。自定义策略还可控制空 Referer；通配符语义与全局一致。原图和缩略图直链应用有效策略，分享内容和解锁不受此策略限制；移动图片立即切换为目标相册策略。

相册策略不会覆盖管理端或上传接口规则，也不会授予其他账号发现、编辑相册的权限。访问私有直链仍需本人或管理员会话，单图分享仍需有效令牌、密码及期限检查。

## 反向代理真实 IP

默认只使用 TCP 连接来源地址，忽略客户端转发头。代理部署时在后台“系统设置 → 站点与代理”填写可信代理 为后端实际连接到的代理 IP/CIDR，例如 `127.0.0.1/32,::1/128`（仅当代理确实运行在同一主机）。容器网络需要使用代理容器地址或受控网络的实际 CIDR；不要直接信任 `0.0.0.0/0` 或可由非代理客户端接入的整个网段。

代理发送 `X-Forwarded-For`，后端只有当前一跳可信时才从右向左继续解析，直到第一个不可信地址。统一镜像由 Go 直接提供服务，外层 HTTPS 反向代理需要正确追加该头；Vite 开发代理保持本机来源，不用于生产真实 IP 判断。外层代理链的每一跳都需要正确追加并受到网络访问约束。

Docker Compose 统一服务只将端口映射至宿主机回环地址。默认信任列表留空，避免自动信任不明网络；先检查部署网络，将实际代理地址加入后台列表并保存（即时生效），然后在“访问控制”中确认当前 IP 正确，再启用白名单。多层代理不要假定设置 X-Real-IP 就足够。

## 缓存与应急

访问检查发生在读取存储和 ETag / 304 判断之前。图片及分享资源始终使用 `Cache-Control: private, no-store`，不得由 CDN 或反向代理共享缓存。若此前 CDN 已缓存公开图片，开启限制时还需主动清缓存并关闭该路径的强制缓存。已下载的副本不能被撤回。S3 Bucket 必须私有，图片只能走 QPix 网关。

无法登录时，在服务端临时设置 `QPIX_DISABLE_ACCESS_RULES=true` 并重启；原规则保留，管理页显示应急状态。修正规则后设回 `false` 并重启。应急开关不跳过登录、角色、资源归属、分享密码/期限、CSRF 或 Origin 检查。详细资源权限见 [permissions.md](permissions.md)。
