# QPix 权限与功能方案

状态：用户已确认实施账号/相册权限，并追加每用户容量与单张限制、密码/到期/撤销分享。日期：2026-10-21。当前实际行为见 permissions.md，验证结果见 verification.md。

入口修正：不提供访客预览入口或公开相册目录；访客通过用户给出的图片链接或指定目标的分享链接访问。

登录修正：管理员与普通用户使用统一登录入口，只输入用户名、密码；后端识别角色并应用对应网络规则与菜单权限。

## 1. 已确认的需求

- Go + GORM 后端，Vue + TypeScript 前端，支持 SQLite / PostgreSQL / MySQL。
- 本地与 S3 多存储、上传压缩、IP / Referer 规则继续复用现有实现。
- 相册按具体账号授权，支持未登录访客和普通用户。
- 普通用户可以浏览、上传和管理自己上传的图片；管理员可以管理所有用户的图片。
- 仍处于初始开发阶段，本方案不安排旧数据迁移或旧链接兼容。开发测试数据不作为权限设计约束。

## 3. 权限设计：建议本轮实施

### 3.1 身份与账号

保留固定的管理员、普通用户两种账号角色；访客表示未登录状态，不保存成账号。注册继续关闭，普通账号由管理员创建。增加账号启用/停用、管理员重置普通用户密码、用户修改本人密码。

停用账号或重置密码时撤销对应会话与 Token。普通用户只能修改本人密码，不能修改账号角色或操作用户管理。账号第一版采用停用管理，避免删除账号时连带改变图片归属。保护最后一个可用管理员。

### 3.2 相册规则

相册设置包含两个独立项目：

1. **允许访客通过图片链接访问**：默认关闭；开启后访客凭收到的链接只读查看对应图片，不提供公开相册目录。
2. **授权用户**：选择具体普通账号。被选中的用户可浏览、上传，并管理本人上传的图片。

开放访客查看不会授予普通用户上传或编辑权限。管理员管理所有相册、授权与图片；第一版由管理员创建、重命名和删除相册，普通用户管理图片。

| 操作 | 访客 | 普通用户 | 管理员 |
| --- | --- | --- | --- |
| 通过链接查看允许访客访问的图片 | 允许 | 允许 | 允许 |
| 通过指定目标的有效分享链接查看图片或相册 | 允许 | 允许 | 允许 |
| 浏览私有相册、图片 | 禁止 | 被授权才允许 | 允许 |
| 上传到相册 | 禁止 | 被授权才允许 | 允许 |
| 重命名、移动、删除图片 | 禁止 | 相册权限有效且为本人上传 | 所有用户的图片 |
| 相册与成员管理 | 禁止 | 禁止 | 允许 |
| 存储、处理、访问规则、账号管理 | 禁止 | 禁止 | 允许 |
| 修改本人密码 | 不适用 | 允许 | 允许 |

未分类空间按上传者隔离，仅本人和管理员可见；普通用户可上传到自己的未分类空间。移动图片不会改变上传者归属，目标相册须具备上传权限。图片移入相册后继承目标相册的访问规则；撤销授权后，该用户停止在该相册内的访问和操作。

删除相册保留图片并返回各上传者自己的私有未分类空间。界面应说明该操作会收回原相册的访客和成员访问，不能把图片默认移到公开区域。

### 3.3 前后端入口

- 登录页仅提供账号登录；访客通过收到的图片链接或有效分享链接访问。
- 普通用户提供“可访问相册”“我的图片”“上传”“账号设置”。“我的图片”仍受当前相册访问权限约束。
- 相册卡片显示私有/访客可见状态；管理员可打开权限弹窗切换访客访问并选择账号。
- 管理员保留图片空间与系统管理两组菜单，增加“用户管理”；图库可按上传者筛选，默认可查看所有图片。
- 普通用户只收到上传所需的存储名称、ID、大小/格式与处理设置，不返回存储目录、Endpoint 或凭据。
- 图片详情按当前用户能力显示操作按钮，后端对每次修改重新鉴权。

### 3.4 图片外链与网络规则

原图、缩略图、列表、搜索、计数均应用同一套相册访问条件。访问判断在读取存储和 ETag / 304 之前执行；无权访问时不返回私有资源详情。

私有图片默认依赖登录会话，可用于同站点查看；复制原图 URL 不会绕过权限。跨站展示使用访客可见相册，后续可增加专用分享链接。授权相关响应禁止共享缓存；S3 保持私有，继续经 Go 网关访问。

现有 IP / Referer 与相册权限叠加，均满足才允许。管理员和普通用户统一登录，后端按账号实际角色应用 admin 或 images 网络规则；管理员不能绕过管理限制，普通账号不会被管理白名单误挡。上传继续适用上传规则，图片与分享链接适用图片访问规则。

`QPIX_DISABLE_ACCESS_RULES` 只跳过原有 IP / Referer 条件，不跳过登录、角色、相册授权或图片归属检查。

### 3.5 上传 Token

普通用户可创建和撤销本人的上传 Token。Token 只执行上传，不能读取私有图片或使用管理接口。上传时检查账号状态与目标相册权限，撤销相册授权后旧 Token 也不能继续向该相册上传。

Token 上传者以 Token 所属账号为准，不能通过请求参数冒充其他上传者。后台写入接口同样检查 CSRF、来源和角色。用户不能借更换图片 ID、相册 ID、批量请求或移动操作越权。

### 3.6 数据结构与实现方式

复用 images.user_id 表示上传者。最小增加：

| 对象 | 变更 |
| --- | --- |
| users | role、enabled |
| albums | guest_visible，默认 false |
| album_members | album_id、user_id 联合唯一，相册与账号对应关系 |

在 app 包集中实现“可查看相册/图片”“可上传到相册”“可管理图片”等判断与查询条件。以数据库查询过滤列表、分页、统计，避免先分页再过滤漏出总数。授权更新与上传/移动的引用建立需要协调，避免权限撤销和写入交错。

无需引入通用权限框架、角色组编辑器、Redis 或新进程。继续单实例运行。

## 4. 后续功能候选

复杂度是相对当前代码的工程判断，不是工期承诺。下表均为待选范围。

| 优先级 | 功能 | 具体范围 | 复杂度 | 主要成本或边界 |
| --- | --- | --- | --- | --- |
| P1 | 回收站 | 删除后外链立即失效；保留 7 天；恢复、手动清空、到期清理 | 中 | 复用 ready/deleting 状态机；恢复时重查相册与用户权限；回收站仍占空间 |
| P1 | 用户配额 | 每用户容量、单张限制、每天上传数；显示已用/剩余 | 中 | 并发上传须预占额度，失败释放；三个数据库均需验证 |
| P1 | 批量移动与筛选 | 批量归类；按上传者、日期、格式、大小、相册筛选 | 低至中 | 批量请求逐项检查归属与目标权限，部分失败明确返回 |
| P1 | 操作记录 | 账号、相册授权、上传、移动、删除及存储变更记录，默认保留 30 天 | 中 | 保存操作者、对象、时间和结果；不记录密码、Token、密钥或完整请求体 |
| P2 | 分享链接 | 管理员分享指定图片或相册，只读；可设置密码、期限、撤销 | 中 | 私有相册的分享是显式只读授权；分享页中的图片/缩略图同样验证分享凭据 |
| P2 | 图片处理预设 | 最长边、输出质量、图片水印；文字水印独立选项 | 中 | 限制处理像素和并发；中文水印需要字体；GIF 等动画保持原样 |
| P2 | 导出与备份辅助 | 导出元数据清单、相册图片打包、展示全部存储与主密钥备份范围 | 中 | 大相册流式打包；导出权限与相册一致；包含密钥的备份仅管理员使用 |
| P3 | 重复上传提醒 | 同用户、同相册中按原始字节 SHA-256 提醒重复，可继续上传 | 低至中 | 先提示，暂不合并物理对象，避免跨权限共享与引用计数 |
| P3 | 存储迁移工具 | 选图复制到另一个已配置存储、校验内容、切换引用 | 高 | 失败可重试；切换后再安排旧对象清理；普通切换默认存储仍不迁移旧图 |

### 推荐的产品取舍

- 回收站能直接降低多人误删损失，建议在分享和水印前完成。
- 配额与操作记录随多用户使用一起考虑；按需保留简单配置，不扩展计费套餐。
- 图片处理优先固定预设；兰空云处理文档也建议谨慎开放任意参数，QPix 第一阶段不开放任意宽高/滤镜的实时变换接口。
- 远程 URL 导入只有明确需求时再做，届时需处理内网访问、重定向、响应大小和超时等问题。
- 当前使用场景优先账号协作、相册管理与分享；支付、工单、短信、开放注册、社交广场和 AI 功能暂缓。

## 5. 推荐分期

### 第一轮：账号与相册权限

实施第 3 节全部内容，包含账号管理、普通用户/访客入口、相册成员、图片归属校验、受保护外链、普通用户上传 Token 和网络规则分流。

涉及文件：

- `backend/internal/database/models.go`、`database.go`：数据模型与开发建表流程。
- `backend/internal/app/app.go`、`auth.go`、`manage.go`、`images.go`、`access.go`：认证、路由、列表/统计、图片读写权限与网络规则；新增权限和用户管理文件。
- `frontend/src/App.vue`、`types.ts`、`api.ts`、`style.css`：身份、页面与请求处理；新增用户管理、相册授权、访客/用户浏览组件，调整 UploadPanel 与 ImageDetail。
- `docs/api.md`、`access.md`、`verification.md`、README：接口、权限规则和验证记录。
- 对应后端测试与浏览器验收。测试数据使用独立账号/相册，不以兼容旧开发数据作为验收标准。

验收：管理员、授权用户、未授权用户、访客四种身份；私有与公开相册；本人/他人图片；授权撤销、账号停用、Token、移动与批量请求；GET/HEAD/304 和缩略图均不得绕过权限。SQLite 必测，PG/MySQL 沿用现有数据库测试矩阵，有可用连接时实测。

### 第二轮：使用保护与管理效率

回收站 → 用户配额 → 批量移动/筛选 → 操作记录。分别形成独立需求和验收范围。

### 第三轮：对外分享与处理能力

密码/到期分享 → 图片处理预设与水印 → 导出工具。重复提醒和存储迁移根据实际使用再排期。
