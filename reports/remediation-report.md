## 二、通用性能整改

| 编号 | 状态 | 整改结果与边界 |
| --- | --- | --- |
| P1 | 已完成 | 与 S1 合并处理；策略锁保护必要的状态校验与数据库写入，删除文件在锁外进行；删除相册只同步清理该相册的图片快照。仍保留短时策略写锁，部署模式仍为单实例。 |
| P2 | 已完成 | 无有效网络限制、允许访客访问且未携带 Token 的直链使用 `private, no-cache, must-revalidate`；其他受限图片及分享图片使用 `private, no-store`。权限判断先于 304，命中 ETag 后不打开存储对象；不启用共享 CDN 缓存。 |
| P3 | 已完成 | 上传人批量读取，相册及存储计数合并查询；图片管理权限在已有数据中判断；用户容量读取计数列，消除列表逐项附加查询。 |
| P4 | 已完成 | 配置锁内只读取必要快照，原图／缩略图存储 I/O 在锁外完成；在途上传计数防止存储位置被并发修改或删除。 |
| P5 | 已完成 | Token 上次使用时间最多约每分钟写入一次，使用数据库条件更新避免并发重复落库，继续校验撤销及到期状态。 |
| P6 | 已完成 | 不透明缩略图使用 JPEG，含透明度使用 PNG；最长边不超过 480px。原图双边不超过 480px、体积不超过 128 KiB 且非 GIF 时直接复用；GIF 单独生成首帧缩略图。兼容旧 PNG 缩略图。 |
| P7 | 已优化 | 接收落有界临时文件，原格式保存采用流式写入，仅符合压缩条件时读取原文件字节。完整像素解码与缩略图仍消耗内存；部署文档补充像素上限和内存关系。 |
| P8 | 已完成 | NRGBA／RGBA 的 PNG 量化直接遍历 Pix，并验证子图步长及透明度。JPEG／PNG 不再共用编码锁；WebP 编码保留独立互斥以约束内存开销。 |
| P9 | 已完成 | 新增 `users.used_bytes` 与迁移版本 7；启动迁移一次性回填，上传及成功删除记录时在事务内增减。物理删除失败仍计入用量，并发清理不会重复扣减。 |
| P10 | 已完成 | 图片与所属相册合并查询；自定义 Referer 编译结果使用有容量及期限限制的缓存。每次仍读取当前策略并比对内容，修改时主动失效。 |
| P11 | 已完成 | 限流表清理由请求按间隔触发，至多每分钟扫描一次，避免超过阈值后每次请求遍历整张表。 |
| P12 | PostgreSQL 有条件完成 | 管理员安装 pg_trgm 后，程序检测并补建图片名称 GIN 索引，也适用于分享中的图片名称搜索。SQLite／MySQL 保留原有子串匹配语义；短搜索词及实际索引选择仍取决于数据库。 |
| P13 | 未纳入 | S3 图片继续由 QPix 网关中转，未增加 CDN 重定向或预签名下载，以维持现有即时权限校验路径。 |

## 三、PostgreSQL 专项

| 编号 | 状态 | 整改结果与边界 |
| --- | --- | --- |
| D1 | 已完成 | 最大连接及空闲连接均为 10；空闲 5 分钟回收、最长存活 30 分钟。未新增连接池后台配置项。 |
| D2 | 已完成 | 启用 `SkipDefaultTransaction`，多语句原子操作保留显式事务。PostgreSQL 未额外开启预编译缓存。 |
| D3 | 已完成 | 迁移版本 8 补建图片索引：`(user_id,state,created_at,id)`、`(album_id,state,created_at,id)`、`(state,created_at,id)`、`(storage_id)`。采用三种数据库兼容的普通复合索引，保留既有索引；用户用量由 P9 计数列解决。 |
| D4 | 代码完成，需安装扩展 | 扩展仅由数据库管理员手动安装；应用每次启动检测 pg_trgm 并补建 `GIN (lower(name) gin_trgm_ops)`。未安装时警告并保留搜索；建索引失败时返回具体启动错误。 |
| D5 | 已完成 | 图库、分享及 Token 网页列表使用游标分页；后续页不再重复 COUNT 或使用 OFFSET。首页返回总数，后续页 total 为 null；保留旧客户端的页码接口及原有排序。 |
| D6 | 已完成主要优化 | 采用 P5 的 Token 写入节流。上传预占记录仍按事务插入和释放，保留容量安全性；未调整 PostgreSQL 刷盘及 autovacuum 配置。 |
| D7 | 已完成 | 配额预占及上传入库的短事务按用户主键执行 `FOR UPDATE`，不同账号的预占可并行；SQLite 保留进程锁。 |

### pg_trgm 部署步骤

由数据库管理员连接 QPix 实际使用的数据库执行：

```sql
CREATE EXTENSION IF NOT EXISTS pg_trgm;
```

应用账号需要建索引权限，扩展所在 schema 需包含在 `search_path` 中。安装后重启应用补建索引；已有大量数据时，应预留首次构建索引的时间。此步骤尚未在实际 PostgreSQL 实例验收。

## 四、SQLite 专项

| 编号 | 状态 | 整改结果与边界 |
| --- | --- | --- |
| L1 | 按确认方案保留单连接 | 已通过消除 N+1、用量计数和游标分页减少连接占用；不引入读写双连接池。 |
| L2 | 按确认方案保留 FULL | 明确使用 `synchronous=FULL`，保留已提交事务的持久性；未采用可能在断电／系统崩溃后回滚近期事务的 NORMAL。 |
| L3 | 已完成 | 普通文件路径内部编码为 URI，由驱动在每次建连时恢复 `busy_timeout(5000)`、`foreign_keys(1)`、`synchronous(FULL)`、`wal_autocheckpoint(1000)`；兼容路径中的空格、中文、#、% 等字符。 |
| L4 | 已完成 | 启动迁移后执行 `PRAGMA optimize=0x10002`；每 10 分钟的现有维护任务执行 `PRAGMA optimize`，按需更新统计信息。 |
| L5 | 已完成安全维护方案 | 后台执行 `wal_checkpoint(PASSIVE)`，外部旧快照读者存在时允许部分完成；不自动强制截断 WAL 或 VACUUM。部署文档提供停服维护说明；检查点不保证文件立即缩小。 |
| L6 | 已完成适用优化 | 复用 D3 的普通复合索引和 D5 的游标分页，用户用量读取计数列；不新增部分索引或 FTS5 虚拟表及同步触发器。 |
| L7 | 保留合理选型 | 继续使用 modernc 纯 Go 驱动及 `CGO_ENABLED=0` 构建，不更换数据库驱动。 |
| L8 | 保持现有约束 | 保持单连接短事务、事务内使用 tx、数据库位于本机磁盘；不增加网络文件系统支持。 |

`QPIX_DB_DSN` 仍填写普通文件路径，用户无需添加 SQLite URI 参数。WAL 模式保留，FULL 配置在连接替换后仍生效。

## 五、MySQL 专项

| 编号 | 状态 | 整改结果与边界 |

| M2 | 已完成 | MySQL 单独启用 GORM 预编译缓存，最多 100 种 SQL、有效期 5 分钟，复用参数化语句；未强制修改 DSN 的参数插值或连接字符集。 |
| M3 | 按确认方案保留 | 继续使用 32 位十六进制随机 ID，未引入主键格式变更及旧数据转换。 |

| M5 | 已完成适用优化 | 使用 D3 的普通复合索引、P9 的用量计数及 D5 的游标分页；不使用 MySQL 不支持的部分索引或 INCLUDE，不自动删除既有索引。 |
| M6 | 已完成 | 按用户主键等值行锁串行化同账号的配额操作，不对预占表按 user_id 范围执行 `FOR UPDATE`。 |
| M7 | 已完成后台分批清理 | 过期登录及分享会话每批最多删除 1000 条，缩短单次锁与连接占用。改密、修改 Cookie 策略等安全操作仍在原有事务中原子撤销会话。 |
